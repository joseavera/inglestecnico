Punto de partida: la gramática como código fuente de la comunicación

Mixtle dice…

«Piensa en una oración como si fuera una función. En voz activa, el sujeto es quien llama a la función: “The developer deploys the app” es como escribir developer.deploy(app): sabemos exactamente quién ejecuta la acción. En voz pasiva, el foco cambia al objeto que recibe la acción: “The app is deployed”. Esto es exactamente lo que pasa en un pipeline de CI/CD: el código se despliega automáticamente y, muchas veces, no importa —o no sabemos— qué proceso específico lo ejecutó. Por eso la voz pasiva es la estructura dominante en la documentación técnica: describe qué pasa, no necesariamente quién lo hace.»

Así como un programa necesita una sintaxis correcta para compilar sin errores, un texto técnico necesita una gramática correcta para comunicarse sin ambigüedad. Hoy vamos a revisar tres tiempos verbales que aparecen constantemente en la documentación de sistemas computacionales, y después nos enfocaremos en la estructura que más se repite en manuales, READMEs y bitácoras: la voz pasiva.

Tiempos verbales esenciales en documentación técnica

Estos tres tiempos cubren la mayoría de las situaciones que encontrarás al leer o escribir documentación de software y sistemas.

Tiempo verbalEstructuraUso técnicoEjemplo
Simple Present subject + verb (-s) Especificaciones y comportamiento habitual del sistema The server processes requests every 200 milliseconds.
Simple Past subject + verb (-ed / irregular) Bitácoras, reportes de incidentes, historial de cambios The system crashed at 3:00 a.m.
Present Perfect subject + have/has + past participle Cambios recientes con relevancia actual (changelogs, status reports) The team has updated the API documentation.

La voz pasiva en el inglés técnico

Fórmula subject + to be (conjugado) + past participle [+ by + agente]

El agente (quién ejecuta la acción) es opcional: se omite cuando es desconocido, irrelevante o cuando el sistema mismo lo ejecuta automáticamente.

Compara cómo la misma información cambia de enfoque según la voz utilizada:

Activa The system administrator configures the firewall every month. Pasiva The firewall is configured every month (by the system administrator).
Activa The CI/CD pipeline tests the code automatically. Pasiva The code is tested automatically (by the CI/CD pipeline).
Activa The development team deployed the new update last Friday. Pasiva The new update was deployed last Friday (by the development team).
Activa A hacker attacked the network last month. Pasiva The network was attacked last month.

En el último ejemplo el agente se omitió por completo. Es una de las razones más comunes para usar voz pasiva en ciberseguridad y en bitácoras técnicas: muchas veces no se sabe quién ejecutó la acción, así que el texto se enfoca en lo que le ocurrió al sistema.

Presente pasivo vs. pasado pasivo

FormaEstructuraEjemplo
Presente pasivoam / is / are + past participleThe code is reviewed before every merge.
Pasado pasivowas / were + past participleThe server was restarted after the update.
Presente perfecto pasivohas / have been + past participleThe operating system has been updated recently.

Ejemplo resuelto: leyendo un fragmento de changelog

Fragmento de un README / changelog de software
“The application is built using Docker. Last week, the database was migrated to a new server. Since then, response times have improved significantly. The API documentation is updated automatically every time a new endpoint is added. Yesterday, a critical vulnerability was discovered and immediately patched by the security team.”
  1. 1Localiza el presente pasivo: is built, is updated → describen procesos automatizados y recurrentes del sistema.
  2. 2Localiza el pasado pasivo: was migrated, was discovered, (was) patched → describen eventos puntuales ya terminados.
  3. 3Localiza el presente perfecto: have improved → un cambio que ocurrió en el pasado reciente y que sigue siendo relevante ahora.
  4. 4Observa que el foco siempre está en el sistema (the application, the database, the vulnerability), no en la persona que ejecutó la acción.
Resultado: identificar la voz y el tiempo verbal te permite distinguir, de un vistazo, qué es automático, qué ya se resolvió y qué sigue vigente.

Actividad práctica

Ejercicio 1 · Transforma de voz activa a voz pasiva

Reescribe cada oración en voz pasiva, conservando el tiempo verbal original.

  1. The programmer writes the code in Python.
  2. The team deployed the application to the cloud last night.
  3. The IT department backs up the servers every night.
  4. The QA team tested the new feature yesterday.
  5. Someone has updated the operating system recently.
Ver respuestas

1. The code is written in Python (by the programmer).
2. The application was deployed to the cloud last night (by the team).
3. The servers are backed up every night (by the IT department).
4. The new feature was tested yesterday (by the QA team).
5. The operating system has been updated recently.

Ejercicio 2 · Completa el changelog

Conjuga cada verbo del banco de palabras en voz pasiva, con el tiempo verbal adecuado según el contexto.

fix · release · encrypt · review · back up

Version 2.3 ______ (release) last Tuesday. Three critical bugs ______ (fix) by the development team. All user data ______ (encrypt) before it is stored on the server. Every pull request ______ (review) by at least two engineers before it is merged. The entire system ______ (back up) automatically every night.

Ver respuestas

was released · were fixed · is encrypted · is reviewed · is backed up

Reto para tu portafolio: busca un fragmento real de un README o manual de software (por ejemplo, en GitHub o en la documentación de Python) y subraya las oraciones en voz pasiva. Reescribe dos de ellas en voz activa e identifica el tiempo verbal utilizado. Guarda este fragmento como evidencia para tu glosario técnico ilustrado, producto de la Unidad 1.

Cierre de la sesión

Síntesis

Hoy repasaste tres tiempos verbales clave —simple present, simple past y present perfect— y aprendiste a construir la voz pasiva en presente, pasado y presente perfecto. Estas estructuras son las que dominan la documentación técnica de sistemas computacionales, porque describen procesos y estados del sistema sin depender de quién ejecutó la acción. En el Tema 1.3 aplicarás directamente estas estructuras a la lectura de manuales y especificaciones técnicas completas.

Conclusión

Así como un programa necesita una sintaxis correcta para ejecutarse sin errores, un texto técnico necesita una gramática correcta para comunicar sin ambigüedad. La voz pasiva, en particular, es la estructura que domina la documentación de sistemas computacionales: manuales, READMEs, changelogs y bitácoras de incidentes la usan constantemente porque el protagonista casi siempre es el sistema —el servidor, la base de datos, el código— y no la persona que lo operó. Dominar esta estructura no es solo un ejercicio gramatical: es la llave para leer con fluidez cualquier documentación técnica en inglés que encuentres en tu carrera.
